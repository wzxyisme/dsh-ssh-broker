# SSH 设备

在本机 Harness 的「设置 → SSH 设备」创建或解锁凭据库。每台设备保存各自的凭据和权限，可单独变更或删除。

### 核对主机指纹

在目标服务器的可信控制台（如云厂商控制台）执行下面的命令。设置页也提供「复制命令」。

```sh
ssh-keygen -E sha256 -lf /etc/ssh/ssh_host_ed25519_key.pub
```

将输出中以 `SHA256:` 开头的字段填入设置页。若 SSH 服务使用其他主机密钥，换成对应的 `.pub` 文件。不要把未经可信渠道核对的网络扫描结果当作可信指纹。

### 授权时限

选择设备、活跃的 Harness 会话和权限范围。默认「限时有效」为 300 秒，可设为 1 至 900 秒。长任务可选「本次会话有效」，核对设备、会话和操作范围后再次确认。只要这类授权仍生效，凭据库就不会因空闲上锁；最后一条结束后，恢复十分钟空闲上锁。关闭浏览器标签页不一定关闭 Harness 会话。

会话关闭、Harness 退出或重启、撤销、库上锁或插件停用都会结束授权并关闭相应的活动连接。轮换或更新连接端点只撤销受影响设备的授权。

### 在输入框提交 SSH 任务

在会话的空输入框点击「＋」，从「指令」中选择 `/ssh-broker`，也可以直接键入 `/ssh-broker`。填写任务后发送。当前会话只有一台设备获授权时，默认自动选择。多台设备获授权时，在输入框上方明确选择一台。发送时插件会复核授权，并把对应工具和授权 ID 随任务传给该会话。授权已失效时，先到设置页为会话重新授权。

`0.4.0` 将 `ssh_exec`、`ssh_upload`、`ssh_download` 分别更名为 `dsh_ssh_broker_exec`、`dsh_ssh_broker_upload`、`dsh_ssh_broker_download`。请更新写有旧工具名的提示词或脚本。

### 助手文件传输

每次创建授权时默认为「仅 Shell」，文件传输关闭。先选设备和会话，再选「仅文件传输」或「Shell 和文件传输」，填写一个已存在的远端绝对目录，最后确认授权。默认只允许传输授权根目录的直属文件。勾选「包含子目录」后，即可列出子目录并传输其中的文件。如果需要更改范围，先撤销该设备的当前授权，再重新授权。

- 在设置的授权列表点击「预览目录」，可以查看授权根目录下一层的普通文件和子目录。预览结果只显示在设置页。也可让助手通过 `dsh_ssh_broker_list` 按需列出一层目录。每次最多返回 100 项，达到读取上限时标记为不完整。
- 上传附件时，把文件作为同一条任务的附件，写明附件名和远端文件名。不同内容用了同一个附件名时，请改名后重新上传附件。下载返回当前会话的 DSH 文件附件。
- 上传工作区文件时，例如发送 `/ssh-broker 将 @docs/report.md 上传为 report.md`。带空格的路径可写 `@"docs/my report.md"`。路径相对于会话创建时记录的工作区，不随 `cd` 改变。每次都要在 DSH 审批中核对本地文件、设备和远端完整路径；拒绝、撤销或审批不可用时不会上传。此功能需要 Linux 上可访问本机工作区的 DSH 文件系统和 `/proc/self/fd`。只接受单个普通文件，拒绝绝对路径、`..`、符号链接与多重硬链接；文件在审批后发生变化时需重新发起。没有可用工作区或审批渠道时，可改用会话附件。
- 开启子目录权限后，可以用相对于授权根目录的路径，例如 `reports/summary.txt`。SFTP 工具拒绝绝对路径、`..` 和符号链接。传输每次处理一个普通文件，最多 8 MiB、60 秒。上传需要服务端支持 OpenSSH `hardlink@openssh.com`，同名目标会阻止上传。断线或撤销时，远端可能留下 `.dsh-sftp-` 临时文件。若提交结果不确定，先在目标机核对同名文件和残留，再决定是否重试。
- 目录检查仅约束 SFTP 工具，依赖可信目标机和稳定的目录。请使用独立低权限 SSH 账号，以及其他不受信任用户无法修改的目录及父目录。需要远端强隔离时，由目标机通过权限或 SFTP chroot 强制执行。组合授权中的 Shell 可使用 SSH 账号已有的全部权限。

命令以目标 SSH 账号的现有权限执行。调用上限 30 秒，无 PTY，stdin 为 EOF，stdout 和 stderr 各保留最多 8 KiB。超时返回 `timed_out`，并附带超时前已收到的输出和相应截断标记。此时输出可能不完整，远端操作可能已经产生影响，重试前请先核对结果。断开连接后，脱离 SSH 会话的进程可能继续运行。命令及其输出可能保存在会话记录中，请避免在命令中包含秘密。

凭据和设备资料保存在当前 Profile 的加密库。重启或热重载会使库上锁；没有会话有效期授权时，连续十分钟无使用也会自动上锁。加密防护依赖口令强度。凭据库解锁期间，安全性依赖可信的宿主及同用户进程。进程强制退出后，库的 `.lock` 文件可能保留。确认所有使用该库的 Harness 进程已退出后，才可移走对应的 `.lock` 文件并重新解锁。

升级旧版时，先关闭所有仍在使用旧插件的 Harness 实例，然后在新版设置页显式迁移。迁移核验旧凭据的设备绑定，验证加密提交后清理旧记录。发生清理错误时按页面提示重试。旧备份可能仍含明文，已有真实凭据应在目标端轮换。

通过「下载加密备份」用独立强口令导出。创建并解锁一个空库后导入，恢复会自动上锁。重新解锁后，逐台核对指纹并保存，再创建新授权。请单独保管备份和对应口令。迁移 Profile 前请从此页面导出，普通 DSH 配置备份不应作为 SSH 凭据库的恢复来源。旧版明文记录也可能留在历史备份或配置管理器的本机镜像中，迁移不会清除这些副本。
